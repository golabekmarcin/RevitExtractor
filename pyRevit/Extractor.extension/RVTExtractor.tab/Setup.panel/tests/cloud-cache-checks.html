Cloud Cache Checks

Three small jobs that tell us how the export button should handle cloud (ACC) models. You type a few IDs into the box in Job 0, and every command on this page fills itself in. You copy, paste, wait, and send me the text it prints.

One file that works offline in any browser on the Revit PC: double-click it, fill in the boxes, copy the commands.

The idea, explained simply

When you open a cloud model, Revit quietly keeps a photocopy of it, and of every linked model, in a hidden folder on your PC (the CollaborationCache). Last time we proved that a photocopy exists for all 28 links. The copies just have number-names (GUIDs) instead of real names.

The exporter finds links by their real file name. So the question is simple: if we take the photocopies, give them their real names and put them in one folder, will the exporter accept them?

If yes, cloud export can be fast and easy. If no, the button must download fresh copies through Revit instead, which is slower.

Three ground rules (client data):
  • Everything goes into C:\RX-private\. Never into the RevitExtractor repo folder.
  • Never git add or commit anything from these jobs.
  • Send results by pasting them into the Claude chat only.

Collect the IDs

5 minutes · Revit open

  1. In Revit 2022, open the same cloud model as last time.
  2. Hold Shift and click Export setup. The cloud check report appears in the pyRevit window.
  3. In the [model] block at the top, find model_guid: and title:. Copy them into the first two boxes below.
  4. Pick two or three small links, because big ones take a long time to copy.
    • In the [cache files naming a known GUID] list, find lines with \LinkedModels\ and a small size, for example under 100000000 B (100 MB).
    • Copy the GUID from the file name, then find the [link …] block whose resource0_info_LinkedModelModelId: is that GUID. Its name: line is the real file name.
  5. Also type the folder where RevitExtractor is cloned on this PC.
