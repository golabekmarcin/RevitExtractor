# Spec: index-builder

Module of `SPEC.md`. Depends on: `capabilities`. Status: **written under the owner's working mode of 2026-11-10** (no per-spec approval; follows Q1–Q29 and `SPEC.md`).

## Objective

One `build_index` for every Revit version, driven by `rx_capabilities`, that writes exactly what today's two buttons write (v1 criterion 9). `export-runner` and `export-button` use it. The old buttons are not touched.

## Interface (`lib/rx_index.py`, pure Python, no Revit import)

```python
build_index(caps, settings=None, selected_2d=None, selected_3d=None)  # dict; raises SetupError
defaults(caps)                         # the settings defaults of that table row
database_warning(caps, settings=None)  # "" unless some Extractor build can't switch the DB off
to_json(index)                         # indent 2, ensure_ascii False, trailing newline (as today)
require_index_shape(data)              # shared index.json (Q18): metadata.parameters.derivative_type
SetupError(ValueError)
```

`caps` comes from `rx_capabilities.for_revit`. Window helpers (`tick_targets`, `toggled_state`, `filter_records`) do not move here; `export-button` owns them.

## Behaviour per table row

| | Rows with `view_ids` (2022–2025) | Newest row (2026 and later) |
| --- | --- | --- |
| Source of truth | `ExportSetupLegacy/extractor_config.py` | `ExportSetup/extractor_config.py` |
| Defaults | its 9 keys | its 13 keys |
| Selected views | `view_ids`: sorted unique integers, 1…2147483647, from ints or digit strings | `view_unique_ids`: sorted unique non-empty strings |
| `dwg`, `ifc`, `ifc_setup_name` | `SetupError` | `export.to`, `direct_params.IFCExportOption` |
| `extended_properties`, `topology_metadata` | `SetupError` | `metadata.extended_properties` (only with the DB on), `3dviewing.topology_metadata` |
| DB off, 3D on | also `3dviewing.db_export: false` | not written |
| Nothing enabled | `SetupError` (2D, 3D, DB) | `SetupError` (2D, 3D, DB, DWG, IFC) |

- **Capabilities amendment.** The table gets one more field, `db_export_key` (True for the 2022 row, False for the 2026 row), and `SPEC-capabilities.md` is corrected. Its sentence "always writes `db_export: false` … as today" is true only for the legacy button; today's 2026 button never writes that key. Old-shape Extractor builds (2024.0.x) ship only with Revit 2025 and earlier, so a row field is factually right. `index-builder` never compares years itself.
- **Deliberate differences, invalid input only.** The 2026 button iterates a string selection per character and raises `TypeError` for a non-text scope (`CLAUDE.md`). Here both raise `SetupError`, as in the legacy button. Messages become bilingual; the Polish text stays as it is.
- Parity means equal parsed content. Key order in the JSON text follows the dict order of the engine and is not significant to the parser.

## Acceptance criteria

1. For `caps` of 2022, 2023, 2024 and 2025, `build_index` equals the legacy builder's result for a matrix of settings and selections that covers at least the nine native-check profiles and every case in `LegacyConfigTests`. `to_json` text is equal on CPython. Where the legacy builder raises `SetupError`, this one raises it with the same English and Polish message.
2. For `caps` of 2026 and 2027, the same against the 2026 button's builder, covering every case in `test_config.py`. Its `SetupError` cases raise `SetupError` whose Polish text equals today's.
3. The two deliberate differences are tested: a string selection and an unknown scope (text and non-text) raise `SetupError` on every row.
4. `build_index(caps)` with no arguments equals the default index embedded in `Start-RevitExport.ps1`, for every row. The test reads the JSON out of the `.ps1`.
5. `rx_capabilities` has `db_export_key`; its tests and `SPEC-capabilities.md` are updated.
6. `database_warning` returns today's legacy text when `caps.db_export_key` and the DB and 3D are both off, otherwise `""`.
7. `require_index_shape` accepts every `build_index` result and the launcher default, and raises `SetupError` for a missing level, a non-dict and `None`.
8. `lib/rx_index.py` imports nothing from `pyrevit`, `Autodesk`, `System` or `clr` (AST test). Every message goes through `tr` with English and Polish.
9. Native parser check passes on this machine for indexes generated by `lib/rx_index.py` (see Testing).
10. `git diff --stat` touches neither old bundle.

## Testing

- New `tests/test_index.py`. It loads both old builders by file path under unique module names (the pattern of `test_config_legacy.py`), appends `lib/` to `sys.path`, and runs the parity matrix.
- `validate_native_legacy.ps1` is extended, not replaced:
  - each of the nine profiles is generated by the legacy bundle **and** by `lib/rx_index.py`; the script fails if the two differ, then parses the lib result natively (9 PASS expected here, Extractor 2024.0.x);
  - a second set for the newest row (DWG + IFC, IFC setup name, extended properties, topology, selected UniqueIds) is generated by the 2026 bundle and by `lib`, compared, then parsed. Only properties the installed parser has are asserted; anything else prints `SKIP <name>: needs a newer Extractor`.
- Verified on this machine: unit tests; native parser with the Revit 2023 Extractor.
- Not verifiable on any machine we have: the 2026 row inside Revit, and `view_unique_ids` in a native parser.

## Boundaries

- Never change the old bundles. They are the reference until Q12 deletes them; the parity tests go with them.
- Never widen an export on bad input: an invalid or empty selection raises, it never falls back to the default scope.
- A new index key needs evidence (a parser check or a verification record) before it is written.
